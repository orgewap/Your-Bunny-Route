# Дорожная сеть — редактор OSM с графом полос

Веб-приложение Vue 3 + TypeScript + MapLibre GL JS. Проект основан на загруженной пользователем версии `road-editor-starter` и расширен инструментами из предоставленной записи экрана: отдельными дорожными полосами, узлами графа, связями на перекрёстках и настройкой направлений поворотов.

## Запуск на Windows

Распакуйте архив в удобную папку (например, `Desktop/road-editor-starter`). В CMD:

```cmd
cd /d "C:\Users\orgew\Desktop\road-editor-starter"
npm ci
npm run typecheck
npm run test:topology
npm run dev
```

В архиве находятся исходники без `node_modules` и `.venv`; `npm ci` устанавливает зависимости. Для установки пакетов понадобится интернет. Требуется Node.js 22+.

Обычно Vite открывается по адресу `http://localhost:5173`. Подробная картографическая подложка OpenFreeMap загружается из интернета; импортируемые дороги — из локального `.osm`.

## Что добавлено

- **«Граф полос»** — кнопка в верхней панели при включённом 2D. Полосы показываются отдельными бирюзовыми рёбрами, узлы — маркерами, возможные соединения в пределах общих OSM-узлов — кривыми.
- Клик по отдельной полосе выделяет её и показывает количество входящих/выходящих соединений в инспекторе.
- У выбранной полосы можно задавать направления `налево`, `прямо`, `направо`. Изменение сохраняется в OSM-тегах `turn:lanes`, `turn:lanes:forward` или `turn:lanes:backward`; работает Ctrl+Z.
- **Исправление короткого выступа к оси магистрали**: на схеме 2D и в 3D дорожное покрытие бокового примыкания заканчивается у внешней границы основной дороги. Общие OSM-узлы остаются на месте — это безопасное разделение геометрии дорожной поверхности и экспортируемой топологии.
- Общая дорожная модель для обеих проекций. Отдельных независимых графов 2D и 3D не создаётся.
- Граф строится только по совместимым дорогам **одного уровня**. Пересечения без общего OSM-узла не превращаются в соединения.

## Как проверить примыкание

1. Загрузите `.osm` и найдите четырёхполосную дорогу.
2. Выберите `P` → «Рисование» и начните новую двухполосную дорогу от крайнего края главной дороги. Закончите её и подтвердите примыкание.
3. Выделите новую дорогу. **В 2D и 3D не должно быть выступа** дорожного покрытия от внешней границы магистрали к её оси.
4. В 2D нажмите **«Граф полос»**. Увеличьте карту до масштаба 15+; отображаются отдельные полосы, узлы и возможные соединения.
5. Кликните по одной из бирюзовых линий и задайте в инспекторе поворот, затем «Сохранить направления».
6. Нажмите **«Экспорт для симуляций»**: редактор проверит OSM и скачает один файл `.osm` для конвертера.

## Остальные инструменты

- `V` — выделение; `Tab` + перетаскивание — перенос всей выделенной дороги.
- `P` — перо: «Рисование», «Кривая», «Свободная рука», «Круг / овал».
- `C` — выбрать кривую в пере.
- `D` — удаление; `Delete` — удалить выделенный участок.
- `Enter` — закончить путь; `Esc` — отменить построение.
- `Ctrl+Z` / `Ctrl+Y` — отмена / повтор; `Ctrl+O` — открыть OSM.
- Поддерживаются 1–10 полос, мосты +1/+2, плавные визуальные подъёмы, сохранение OSM и круговые перекрёстки из пера.

## Экспорт для MATSim / SUMO / Webots

Кнопка **«Экспорт для симуляций»** формирует и предварительно проверяет один OSM 0.6. Конвертер из `traffic-simulators.zip` не меняется:

1. MATSim принимает этот `.osm` напрямую.
2. SUMO принимает тот же `.osm` напрямую.
3. Webots запускается после SUMO и получает `scenario.zip` + `fcd.xml`; отдельный OSM-экспорт для Webots не требуется.

Проверка экспорта валидирует XML, OSM ID, координаты, автомобильные ways и ссылки на узлы/объекты. Координаты должны попадать в UTM zone 48N, потому что MATSim-конвертер использует фиксированный `EPSG:32648`. Новые битые ссылки, созданные удалением дорог, блокируют экспорт. Уже существующие неполные ссылки отношений в исходном обрезанном OSM сохраняются без изменений.

Редактор сохраняет `highway`, `lanes`, `oneway`, `motor_vehicle`, `motorcar`, `bridge`, `tunnel`, `layer`, OSM-отношения и не-дорожные объекты. Если исходная дорога не содержит `lanes`, редактор не придумывает значение: показывает предупреждение, а конвертер применяет свои правила по умолчанию.

Граф полос **вычисляется для редактора**. Разрешённые направления экспортируются тегами `turn:lanes`, однако это не гарантирует точных `lane-to-lane` соединений в SUMO или Webots: конвертеры рассчитывают часть соединений самостоятельно. Дополнительные теги `road_editor:*` не следует считать автоматически поддерживаемыми всеми тремя симуляторами.

В Checker загружается именно `.osm`, а имя файла должно совпадать с именем команды (например, `team1.osm`). Webots-сценарий не нужно создавать вручную: его формирует последовательность SUMO → Webots.

Подробный контракт — [SIMULATOR-EXPORT.md](SIMULATOR-EXPORT.md); отчёт по приложенному файлу — [SIMULATOR-VALIDATION-1-OSM.md](SIMULATOR-VALIDATION-1-OSM.md). Подробнее о графе полос — [docs/lane-graph.md](docs/lane-graph.md).

## Проверка кода

```cmd
npm run typecheck
npm run test:topology
npm run build
```

На среде разработки проверены TypeScript, компиляция четырёх Vue-компонентов и автоматические тесты. Окончательную Vite-сборку в Linux здесь нельзя было запустить с Windows-поставкой нативного Rollup; в Windows проверьте `npm run build`.

## Структура

- `src/components/MapEditor.vue` — карта, 2D/3D, перо и слои графа.
- `src/components/PropertyPanel.vue` — инспектор дорог и настройка поворотов выбранной полосы.
- `src/lib/laneGraph.ts` — граф полос, портов и геометрических соединений.
- `src/lib/roadSurface.ts` — визуальная подрезка примыканий и смещение геометрии полос.
- `src/lib/laneRules.ts` — запись и чтение OSM `turn:lanes`.
- `src/lib/laneSnap.ts` — привязка к видимым полосам и краям.
- `src/lib/topology.ts` — пересечения, общие OSM-узлы и мостовые участки.
- `src/lib/osm.ts` — загрузка / экспорт OSM XML 0.6.
- `src/lib/simulatorExport.ts` — проверка совместимости одного OSM-файла с конвейером MATSim → SUMO → Webots.
- `src/lib/roadMesh.ts` — 3D-поверхности дорог.
- `src/stores/editor.ts` — состояние проекта и Undo/Redo.
- `tests/` — автоматические тесты геометрии, полос, мостов и экспорта.

## Производительность — обновление 2026-11-09

Исправлены задержки при движении мыши, выборе полос и переходе в 3D: рендер и предпросмотр объединяются по кадрам, граф полос и 3D-сетка ограничены видимой областью, больше нет глубокой подписки на все OSM-вершины. Список дорог показывает по 120 записей с кнопкой продолжения; Undo хранит 25 последних операций без проксирования старых координат.

- Граф полос детализируется с масштаба 14; линии соединений показываются с масштаба 16.
- При обычном редактировании можно держать режим графа выключенным; включайте его для локальной проверки.
- Для проверки корректности: `npm run typecheck` и `npm run test:topology`.
- Все выполненные оптимизации, известные ограничения и замеры описаны в [docs/performance.md](docs/performance.md).

Это обновление **не меняет OSM-формат и не гарантирует определённый FPS на конкретной видеокарте**. Если аппаратное ускорение браузера отключено, MapLibre может оставаться медленным даже после оптимизации приложения.

## Совместная работа (технический этап)

Backend теперь поддерживает учётные записи, участников проекта и сохранение независимых изменений пяти редакторов с уведомлениями через WebSocket. Чтобы начать, сначала запустите `py -m backend.create_admin`, затем сервер `py -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1` и редактор `npm run dev`. В приложении кнопка **«Войти»** открывает авторизацию; пользователи и роли управляются внутри «Проектов». Подробная настройка и ограничения — [backend/README.md](backend/README.md).


## Защищённый удалённый доступ команды (Cloudflare Tunnel)

После успешной локальной проверки нескольких участников можно открыть редактор на одном
защищённом HTTPS-адресе. При `ROAD_EDITOR_SERVE_FRONTEND=1` FastAPI раздаёт
готовую Vue-сборку, API и WebSocket с одного порта без запуска Vite dev server.

```cmd
npm run build
scripts\start-remote.cmd edit.example.com
```

Перед публикацией настройте **Cloudflare Access** с разрешёнными email команды,
а в Tunnel включите **Protect with Access** и маршрут `edit.example.com` →
`http://127.0.0.1:8000`. Локальный backend по-прежнему слушает только loopback.
Пароли Road Editor и роли проектов продолжают действовать. Токены туннеля нельзя
сохранять в репозитории. Полные инструкции и порядок проверки —
[docs/remote-access.md](docs/remote-access.md).

## Дополнительная инфраструктура Webots

Кнопки **Webots 3D** и **+ .wbt** в верхней панели готовят дополнения к сцене официального Webots OSM Importer: бордюры, опоры мостов, ограждения, сигналы и разметку. Это отдельный модуль, не меняющий автомобильный граф или базу проектов. Инструкция — [docs/webots-infrastructure.md](docs/webots-infrastructure.md).
