# Backend совместного редактирования OSM — локальная команда

FastAPI + SQLite + WebSocket, без Firebase и внешней базы. Backend **не создаёт пароль по умолчанию**: после установки патча сначала создайте администратора.

## Запуск Windows (CMD)

```cmd
cd /d "C:\Users\orgew\Desktop\road-editor-starter"
py -m pip install -r backend\requirements.txt
py -m backend.create_admin
py -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

В другом терминале:

```cmd
npm run dev
```

Откройте `http://localhost:5173`, нажмите «Войти», используйте логин и пароль, введённые при `create_admin`. Затем откройте панель «Проекты», создайте проект. В блоке «СОЗДАТЬ УЧЁТНУЮ ЗАПИСЬ» создайте 4 дополнительных логина с независимыми паролями (не менее 12 символов), а в блоке «КОМАНДА» добавьте их как редакторов. Каждый открывает один и тот же проект под своим логином.

Обновление существующей базы **сохраняет проекты**. Администратор видит ранее созданные проекты и может назначить к ним участников. Без входа локальный редактор и экспорт OSM по-прежнему доступны, но серверные проекты требуют авторизации.

## Что синхронизируется

- WebSocket `ws(s)://<host>/api/projects/<id>/live` отправляет число участников и события успешных сохранений, но не передаёт целый OSM на каждом движении мыши.
- Клиент с чистым рабочим состоянием загружает новую серверную ревизию; локальные несохранённые правки никогда автоматически не стираются.
- При одновременных изменениях разных OSM-узлов/дорог/отношений сервер делает трёхстороннее слияние. База сравнения хранится **на сервере** в `backend/data/projects/<id>/revisions/*.osm.gz`; браузер не может подделать её.
- При конфликте по одному OSM-объекту возвращается HTTP 409 с ID, первая правка сохраняется, второй участник может скачать свою локальную OSM-копию. Слияние атрибутов одной и той же дороги пока намеренно не делается.
- Роли `owner`, `editor`, `viewer`; записи сотрудников создаёт администратор. Пароли хранятся с PBKDF2-HMAC-SHA256 и индивидуальной солью; токен сеанса — HttpOnly SameSite-cookie, в SQLite хранится только хеш токена.
- Хранится до 24 сжатых ревизий проекта. Если устаревшая ревизия уже удалена, сервер отклоняет слияние, **не перезаписывая** текущий проект.

## Безопасность и тестирование через туннель

Для локального теста backend слушает только `127.0.0.1:8000`, Vite проксирует `/api` (HTTP и WebSocket). Открывать порт 8000 в интернет не нужно. Сервис рассчитан на **один Uvicorn worker**: синхронизация в памяти и файловый lock пока не распределены между процессами.

Если будете тестировать через Cloudflare Tunnel, используйте HTTPS-домен с **Cloudflare Access** и разрешёнными учётными записями. Туннель ведите к frontend/обратному прокси, а не напрямую к backend 8000. Для HTTPS поставьте `ROAD_EDITOR_SECURE_COOKIES=1` при запуске backend. Vite dev server не предназначен для длительного публичного размещения; для постоянной работы нужна production-сборка с обратным прокси, резервным копированием и ограничением размеров запросов. Обычный туннель **сам по себе не заменяет авторизацию**.

## Проверки

```cmd
py -m unittest discover -s backend/tests -v
npm run typecheck
npm run test:topology
```

Данные проекта в `backend/data/` не удаляются после перезапуска. Доступность в браузере на пяти реальных компьютерах и итоговый FPS нужно проверить отдельно.
