# Пешеходный граф и дорожная разметка — обновление редактора

## Режимы сети

Переключатель «СЕТЬ» в правой верхней части карты:

- **Авто** — только автомобильный OSM-граф, настоящие полосы, сплошные/прерывистые/двойные осевые линии, стрелки из `turn:lanes`, дорожная инфраструктура и переходы.
- **Пешеходы** — пешеходные `footway`, `path`, `steps`, `pedestrian`, пешеходные `corridor`/`platform` и пригодные для ходьбы велодорожки, а также тротуары из `sidewalk=*` (пунктир).
- **Обе сети** — два графа одновременно, чтобы видеть переходы и примыкания.

Изменение режима не меняет исходный XML. Сами OSM-ways не дублируются.

## Создать / изменить пешеходную дорожку

1. Выберите «Пешеходы».
2. Нажмите «Перо» (P); доступны режимы рисования, кривая и свободная рука.
3. Укажите точки; End/Enter завершает построение. Конец возле существующей *пешеходной* линии прикрепляется к её OSM-узлу, при необходимости вставляя узел внутрь way.
4. «Выделение» (V) позволяет выбрать дорожку, перетащить вершины, переместить весь объект через Tab или указать свойства дорожки в правой панели.
5. Для отмены Ctrl+Z. Сохранение — штатный экспорт `edited.osm`.

«Круг/овал» используется только для автомобильных дорог и круговых перекрёстков.

## Маршруты и проверка связности

В режиме «Пешеходы» или «Обе сети» выберите инструмент маршрута (M) и нажмите два OSM-узла пешеходной сети. Если маршрут существует, он появится жёлтым цветом с длиной в метрах. Иначе редактор сообщит, что сеть разорвана.

Важно: два перекрещивающихся отрезка **не считаются соединёнными**, пока у них нет общего ID OSM-узла. Отдельно отмеченные тротуары `sidewalk=*` визуализируются пунктиром, **но не включаются в маршрутизацию**: у тега нет отдельных координат и узлов, и автоматически выдавать геометрическую линию за маршрут было бы некорректно.

## Разметка

- Осевая линия (сплошная / двойная / прерывистая / отсутствует) по `divider`, `centre_line`, `road_marking:centre`, `overtaking` и настройкам редактора.
- Линии между автомобильными полосами и краевая разметка. При отсутствии явной маркировки отображение ограничено: редактор не должен выдавать предположение за существующую разметку.
- Стрелки движения по полосам только при наличии `turn:lanes`, `turn:lanes:forward`, `turn:lanes:backward`.
- «Зебра» возле OSM-переходов, когда указана разметка; при неизвестном типе отображается приглушённая **условная** разметка. `crossing=unmarked` и `crossing:markings=no` белую «зебру» не создают.
- 3D: небольшое (0,16 м) поднятие визуального покрытия пешеходных дорожек; это не отдельные экспортируемые OSM-объекты.

Ручные настройки визуального оформления осевой/краевой разметки сохраняются в пользовательских `road_editor:*` тегах. Эти теги сохраняются в OSM XML, но конвертеры SUMO/Webots **не обязаны интерпретировать их как фактические запреты или физическую разметку**. Правила поворотов должны задаваться стандартными OSM-тегами и/или через адаптер симулятора.

## Остающиеся ограничения

- Автоматическое создание новых тротуарных OSM-ways из `sidewalk=*` намеренно не выполняется: пунктир — только визуальное предположение.
- Не реализованы настоящие 3D-пандусы и детализированные ступени лестниц, тактильная плитка, бордюрные съезды, светофорные программы для пешеходов и экспорт связей через SUMO walkingareas.
- Не все виды дорожной разметки в мире кодируются тегами OSM; отсутствующие сведения нельзя восстановить гарантированно только из геометрии.
- При импорте/экспорте сохраняются исходные нераспознанные OSM-объекты. Для транспортного симулятора необходима отдельная проверка его конвертером.

## Проверки

В корне проекта:

```cmd
npm run typecheck
npm run test:topology
npm run build
```

Приёмочное испытание: импортировать `edited.osm`, сравнить 2D «Авто / Пешеходы / Обе сети», выделить `highway=footway`, нарисовать новую дорожку и проверить `edited.osm`, построить маршрут по двум общим OSM-узлам, проверить «зебру» с `crossing:markings=zebra`, проверить сплошную/двойную осевую на явно размеченной дороге и переключиться в 3D/спутник.
