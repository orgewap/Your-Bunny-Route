# Оптимизация редактора — ревизия 2026-11-09

## Исправленные источники нагрузки

1. **Реактивность и редактирование вершин.** Ранее `watch(roads, { deep: true })` обходил каждую вершину всей OSM-сети при каждом изменении. Теперь у хранилища есть лёгкий счётчик `geometryRevision`, инкрементируемый всеми методами изменения дорожной геометрии и тегов. Изменения карты объединяются в один кадр, а во время перетаскивания тяжёлое обновление ограничивается примерно 20 раз в секунду. Сами события мыши продолжают поступать без этой задержки.
2. **3D-сетка.** Ранее меш всех дорог пересоздавался даже при выборе полосы в 2D. Теперь меш строится **только в 3D** и только из участков в области камеры с запасом 250 метров. Для плавных рамп сохранена метрическая интерполяция, но шаг сэмплирования увеличен с 3.5–5 до 6–10 м. Антиалиасинг основного WebGL-контекста отключён, разрешение ограничено 1.5 DPR.
3. **Граф полос.** Пересчитывается только по участкам, видимым в окне карты, а не по всему городу. На масштабе менее 14 подробный граф не строится, связи перекрёстков появляются с масштаба 16. Их число за один кадр ограничено 1300 (ранее 6000). Выбор другой полосы обновляет подсветку без повторного построения геометрии.
4. **Правая панель.** Статистика выбранной полосы рассчитывается для самой дороги и дорог, имеющих с ней общие OSM-узлы. Перестала строить полный граф из всех OSM-way при каждом выборе полосы. В списке показываются по 120 дорог с кнопкой «Показать ещё», поиск работает по всей импортированной сети.
5. **Привязка к полосам.** При перемещении мыши проверяются участки в текущей видимой области, а не весь импорт. Движение пера обрабатывается не чаще одного раза примерно за 20 мс; точные точки по кликам не ограничиваются.
6. **OSM-подложка и предпросмотр.** Одновременные изменения группируются в `requestAnimationFrame`. На обычном движении курсора обновляются только нужные GeoJSON-источники (линия и точка привязки), а не 7 разных слоёв сразу.
7. **Память Undo/Redo.** История хранится в `shallowRef`: Vue не превращает все архивные координаты в реактивные прокси. Для контроля потребления памяти максимальная глубина Undo — 25 шагов (ранее 50).
8. **Поверхность дороги.** Поиск связанных OSM-узлов индексируется за один линейный проход вместо повторного перебора всех дорог для каждого примыкания. Сохранение исходной геометрии проверено тестами.

## Сравнение времени алгоритмов

Синтетическая нагрузка, Node.js 22, текущая среда проверки (не измерение FPS ноутбука):

| Операция | До | После |
|---|---:|---:|
| Построение графа 864 дорог (3456 полос), против 208 видимых дорог (832 полос) | 20.2 мс | 2.6 мс |
| Расчёт поверхности 1000 дорог с короткими примыканиями | 36.7 мс | 3.8 мс |

Эти цифры демонстрируют сокращение работы алгоритмов, но не измеряют MapLibre/WebGL, браузер или реальную частоту кадров на чужом оборудовании.

## Что не менялось

- OSM-узлы, ID, XML экспорт, топология мостов, соединения и правила поворотов.
- Четыре режима пера, круговое движение, Tab-перетаскивание, 2D и 3D.
- Граф полос остаётся **визуальным производным графом**. Точное поведение симуляторов SUMO/MATSim/Webots требует проверки конвертации.

## Запуск и диагностика

В CMD, из корня проекта:

```cmd
npm run typecheck
npm run test:topology
npm run dev
```

На Windows архив содержит те же платформенные зависимости Node.js, что и предыдущий полный архив. Если появилась ошибка нативной библиотеки, установите зависимости заново через `npm ci`. Если интерфейс тормозит даже с пустой картой — проверьте аппаратное ускорение WebGL в браузере (`chrome://gpu` в Chrome). При работе с большим файлом начинайте редактирование с обычного 2D; граф полос включайте на локальном участке и масштабе 16+.

## Известное ограничение

Сложные перекрёстки с многочисленными дорогами всё ещё могут требовать времени на первичный расчёт; в следующем этапе лучше перенести вычисление графа в Web Worker и перейти на пространственный R-tree, если профилирование конкретного файла подтвердит эту необходимость. Не следует ожидать гарантированного FPS без измерения в реальном браузере и на реальной карте.


## Инфраструктура, пешеходный граф и 3D-буферы — ревизия 2026-11-10

1. **Раздельная инвалидация.** Дорожная геометрия, дорожные теги/разметка, статус дорог, инфраструктурные объекты и переходы получили отдельные ревизии. Размещение светофора, STOP или стоп-линии больше не пересобирает всю поверхность дорог, пешеходный граф и индексы города.
2. **Undo/Redo инфраструктуры.** Действия с дорожными объектами сохраняют снимок только коллекции инфраструктуры и вершины одной дороги, если размещение добавило OSM-узел. Полный снимок дорожной сети остаётся для операций с геометрией. Существующие действия Undo/Redo не удаляются.
3. **OSM ID.** Зарезервированные ID собираются один раз при импорте. Размещение каждого нового объекта больше не разбирает весь исходный XML и не сканирует все дорожные вершины для генерации ID.
4. **Привязка объектов.** Индекс дорожных сегментов и карты `osmId`/node ID строятся один раз на ревизию дорожной геометрии. Отрисовка существующих светофоров и стоп-линий использует этот индекс, а не повторно перебирает весь OSM-граф для каждого объекта.
5. **Отдельные GPU-буферы.** Дорожное полотно, статусные контуры, бордюры/опоры/ограждения, знаки/светофоры и пешеходное покрытие обновляются независимо. Изменение светофора обновляет только буфер дорожных объектов; оно не пересоздаёт полотно города.
6. **Пешеходная визуализация.** Пешеходные GeoJSON-источники ограничены буферной областью карты. В 3D добавлено отдельное метрическое покрытие тротуаров и пешеходных дорожек; подземные пути не поднимаются на поверхность. Зебры вынесены в пешеходный буфер и не пересоздаются при изменении обычного светофора.
7. **Выбор объекта.** При выборе дороги не пересоздаются пешеходные поверхности, узлы и порталы; обновляется только слой, который содержит признак выделения. Порталы подземных переходов кэшируются на ревизию дорожной геометрии.

### Проверка на приложенном OSM-проекте

В `workspace.osm` из загруженного архива найдено 3 244 корректно собранных highway-way, включая 1 573 пешеходных way. Функции визуализации сформировали 1 576 пешеходных линий и 1 557 поверхностей; пешеходный граф содержит 4 957 рёбер и 1 491 узел-развилку. 3D-покрытие ограничено 4 800 сегментами на полный уровень детализации.

В этой среде построение 3D-покрытия на таком наборе заняло около 45 мс, создание индекса инфраструктуры — около 32 мс. Это время алгоритмов Node.js, а не замер FPS браузера или компьютера пользователя.

### Что сохранено

- Все текущие инструменты дорог, мостов, круговых перекрёстков, пера и полос.
- Все типы инфраструктуры: светофоры, STOP, уступи дорогу, переходы и стоп-линии.
- Авто/пешеходный/совмещённый режимы, подземные переходы и разметка.
- 2D/3D, спутниковая подложка, проекты, участники и серверная совместная работа.
- OSM-топология, ID, XML-экспорт и backend не переписывались.

Проверки этой ревизии: `vue-tsc --noEmit` без ошибок; 198 тестов прошли. Полную Vite-сборку в Linux-среде не удалось запустить из-за отсутствующего optional package `@rollup/rollup-linux-x64-gnu`; Windows-сборку нужно проверить командой `npm run build`.
