# Стиль пользовательского интерфейса

## Визуальная концепция

Рабочая станция инженера, не landing page и не admin dashboard. Рабочая карта занимает максимум полезной площади; инструменты компактны, свойства доступны справа без диалогового окна. Тёмный интерфейс помогает отделить интерактивные дороги от светлой картографической подложки.

## Правила

- Нейтральные фоны вместо множества насыщенных карточек. Один акцентный цвет — бирюзовый для выбора и действий. Песочный оттенок — мосты. Красный — только удаление и ошибки.
- Радиус элементов 3–7 px, минимальные тени, без градиентов и декоративного glassmorphism.
- Интерфейс: 10–13 px для команд и параметров, 14–15 px для заголовков; плотная сетка 4/8/12/16/24 px.
- Все кнопки инструментов имеют tooltip и горячую клавишу. Поля редактирования имеют подпись и единицы измерения.
- Не показывать фиктивные цифры, проценты готовности или «успешные проверки» без backend результата.
- Ошибки не прятать в toast, если они блокируют экспорт: для MATSim/SUMO/Webots нужна полноценная панель результатов.
- В 3D должна сохраняться та же рабочая модель, выделение и переходы между режимами не требуют нового импорта.
- UI не должен менять граф топологии напрямую: сначала preview кандидатов, затем явное подтверждение пользователя и серверный commit.
- Добавлять интерактивные 2D/3D инструменты только с ясной разницей между геометрическим пересечением и общей топологической вершиной.

## Следующие общие компоненты

`IntersectionChoiceDialog`, `LaneEditorPanel`, `ValidationPanel`, `WarningsList`, `StatusLog`, `ConfirmOperationDialog`, `FeatureSelectionInspector`, `ThreeRoadLayer`.

Не добавляйте их без соответствующей работающей логики: заглушки визуально выглядят завершёнными, но создают проблемы на приёмке.
