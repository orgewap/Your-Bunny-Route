# Webots 3D — дополнительная инфраструктура

Редактор **не переписывает автомобильный граф** для Webots. Полноценные дороги,
перекрёстки и дорожную поверхность создаёт официальный **Cyberbotics OSM Importer**.
Это дополнение из того же исходного OSM создаёт бордюры, ограждения, мостовые
опоры, дополнительную разметку, переходы и статические 3D-светофоры.

## Экспорт из интерфейса

1. Запустите backend (`python -m uvicorn backend.main:app --reload --port 8000`) и
   frontend (`npm run dev`), войдите в учётную запись. В правой панели выбранной
   автомобильной дороги настройте «ИНФРАСТРУКТУРА WEBOTS».
2. Нажмите **Webots 3D**. Скачанный `webots-infrastructure.zip` содержит:
   `webots-source.osm` с границами карты, `extras-to-merge.txt` (геометрия),
   `report.json` и инструкцию. Это **не** готовая сцена с дорогами.
3. Передайте `webots-source.osm` в официальный Webots OSM Importer (если нет
   дополнительных модулей, установите зависимости официального импортёра).
4. В редакторе нажмите **+ .wbt**, выберите **сцену от импортёра из того же
   `webots-source.osm`**. Скачанный ZIP содержит `webots-ready.wbt` с
   дополнительной инфраструктурой. Откройте его в Webots.

Для CLI после использования официального импортёра:

```cmd
python -m backend.webots_extras --osm webots-source.osm --world map.wbt --output webots-ready.wbt
```

Сборка идемпотентна: при повторном вызове предыдущий блок инфраструктуры
заменяется, а не дублируется. Исходный файл .wbt и база проектов не меняются.

## Поддерживаемые теги

| Объект | OSM / локальный тег | Пояснение |
|---|---|---|
| Бордюр | `barrier=kerb` + `height`; `sidewalk=both/left/right`; `road_editor:kerb` | По сторонам осевой линии, высота в метрах |
| Разметка | `road_editor:centre_marking=solid/double/dashed`; `road_marking=stop_line` | Добавляется поверх поверхности Road импортёра |
| Зебра | Узел `highway=crossing` + `crossing:markings=zebra` | Отдельные полоски реального размера |
| Светофор | Узел `highway=traffic_signals`, `traffic_signals:direction`; `road_editor:road` | Столб и три светофорные линзы; положение приблизительно, рядом с дорогой |
| Стоп-линии | `road_editor:stop_line=yes/no`, `road_editor:lanes=2,3` | Для выбранных полос; не изменяет дорожную топологию |
| Мосты | `bridge=yes`, `layer=1/2`, `bridge:support=pier` | Опоры с условной высотой `layer × 5 м`; учитывается `road_editor:bridge_support=none` |
| Ограждения | `barrier=guard_rail`, `road_editor:guard_rail=left/right/both` | Жёсткие сегменты ограждения |

Дополнительные `road_editor:*` теги остаются в локальном OSM-файле. Их не
нужно публиковать в OpenStreetMap. Дорожные `lanes`, `oneway`, `turn:lanes`
по-прежнему остаются стандартными OSM-атрибутами; базовая разметка Road/RoadLine
строится официальным импортёром. Этот экспортёр намеренно не дублирует все
линии дорожного полотна.

## Координаты, уровень и ограничения

- Используется та же проекция UTM и центрирование по bounds, что в Webots
  OSM Importer. ПРИНЦИПИАЛЬНО использовать `webots-source.osm` для обоих шагов.
  Сцена, созданная из иного OSM с другими границами, **не совпадёт по координатам**.
- На 3D-рельефе от импортёра дополнительная инфраструктура пока размещается
  на условной плоскости `z=0`. Нужна отдельная настройка высот.
- Автоматические опоры мостов пропускаются над наземными дорогами, но расположение,
  нагрузка, фундамент и коллизии всё равно требуют проверки в Webots.
- Условная высота `layer × 5 м` не является инженерной высотой моста.
- Светофоры пока **не управляют движением**. Для циклов и фаз нужен отдельный
  Webots Controller или интеграция с SUMO `tlLogic`.
- Полосные связи не создаются в симуляторе этим экспортом. Их надо проверять
  через SUMO/Webots после импорта.
- Сам `.wbt` пока не открывался в установленном Webots при CI-проверке:
  этот проект тестирует синтаксический генератор и API, а не физический движок.
- При `barrier=guard_rail` стандартный импортёр может уже построить ограждение;
  при необходимости отключите импорт barrier в базовой сцене для избежания дублей.

## Проверка

```cmd
python -m unittest discover -s backend/tests -v
npm run typecheck
npm run test:topology
npm run build
```

Модуль добавляет один аутентифицированный endpoint `POST /api/webots/export`,
не меняя API проектов, WebSocket, структуру БД, автосохранение, Undo или
`edited.osm`. При экспорте используется текущая рабочая XML-модель из памяти,
включая ещё не сохранённые локальные изменения.

Дополнительно стандартные OSM `turn:lanes`, `turn:lanes:forward`,
`turn:lanes:backward` преобразуются в **условные** белые стрелки около концов
дорог. Это визуальная разметка, не жёсткая связь полос или правило управления
автомобилем в Webots.
